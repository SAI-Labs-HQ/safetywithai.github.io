Idea 1 of 5

Do LLMs behave differently when the prompter is human vs another LLM?

It seems clear that LLMs can recognize when a text is from a human or an LLM. We could make a reasonable assumption that they "expect" prompts to come from humans, have human style. What happens if the prompt, controlled for content, reads very LLM? Might they behave differently?

Concretely: when the same request is phrased in a human style versus an LLM style, do safety-relevant behaviours of the responding model (for example refusal, sycophancy, compliance, answer accuracy) change? And if they do, is the change driven by the model's internal representation of "this prompt was written by an LLM", or only by surface features such as length, clarity and politeness?

Background given to every method

Why it matters. Most safety evaluations (model-written evals, synthetic red-team prompts, automated auditors) use LLM-written user turns, and in multi-agent systems the orchestrator's prompts to sub-agents are LLM-written. If "reads LLM-written" shifts behaviour, evaluation results may not transfer to deployment with human users.

What is known. The ingredients exist separately. Models can tell evaluation transcripts from deployment transcripts, and synthetic-looking prompts are one cue (Needham et al., 2505.23836), but authorship style was not isolated. Evaluation or test awareness can be probed and steered, and this changes compliance (2505.14617, 2507.01786). Machine-written versus human-written text is linearly separable in LLM activations (RepreGuard, 2508.13152), but those probes are used as detectors and are not connected to downstream behaviour. Self-preference work (Panickssery et al., 2404.13076) studies LLM text as the object being judged, not as the instruction. The closest behavioural analogue looks at prompt construction as a confound for one behaviour only (political stance).

Gap. No paper was found that (a) isolates human versus LLM style of the user prompt with content held fixed, across several safety-relevant behaviours, (b) tests causally whether an internal "LLM-written" representation, rather than surface features, drives any behaviour change, and (c) measures how that representation relates to the evaluation-awareness direction. A purely behavioural comparison without the controls below adds little.

Scope and pitfalls. - Models: gated repos (google/gemma-*, meta-llama/*) need the HF_TOKEN environment variable to have been granted access; if a download is refused, Qwen2.5-7B-Instruct works without it. An OpenRouter API key is available as OPENROUTER_KEY (for example for rewriting prompts and judging responses). - The main confound: content control is leaky. LLM rewrites of a human prompt are typically longer, clearer, more polite and more explicit, so a behavioural difference may reflect clarity or politeness rather than perceived authorship. A result is only informative if it separates "was paraphrased" from "reads LLM" (for example a paraphrase that imitates human style) and checks that the manipulation actually changes whether the model perceives the text as LLM-written. An intervention on activations with the prompt text held exactly fixed is the cleanest form of "controlled for content"; it needs random-direction and norm-matched baselines, because a learned direction may encode length or formality and steering can simply degrade the model. - Headroom: refusal on plainly harmful prompts can be at ceiling or floor for small open models; borderline requests give more room for an effect. API models may refuse to rewrite harmful prompts, which shrinks that subset. - A clean null ("synthetic prompts do not change behaviour once content is controlled") is a useful result if the controls are in place.
